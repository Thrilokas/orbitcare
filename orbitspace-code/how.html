How Orbitspace works

  1. Simulate a mission. 3 astronauts, 180 days of vitals: resting heart rate, heart-rate variability, sleep, blood oxygen, bone density, and cumulative radiation. See js/data.js.
  2. Build a personal baseline. Days 1–21 for each astronaut, per metric (mean and standard deviation). No population average — each person is compared with themselves.
  3. Score every day. Direction-aware z-scores (higher resting heart rate is worse; lower HRV, sleep, SpO2 or bone density is worse), smoothed over 3 days into 4 domain scores: Heart, Bone & Muscle, Sleep & Mind, Immune / Radiation.
  4. Flag in plain language. A z-score of 1.5+ creates a flag, e.g. “Resting heart rate elevated”. The crew list is sorted worst-first so the person who needs attention is on top.
  5. Turn flags into a plan. Rule-based daily action plans (ease workload, protect sleep, bone & muscle session, re-check tomorrow) plus a crew self-check and a downloadable crew report.

Demo story — Day 63

Kenji drifts gradually from around Day 50 and flags Priority #1 in Watch on Day 63. He recovers by Day 90. Amara dips during the Day 118–131 schedule shift. Elena's bone density declines slowly across the whole mission — the quiet risk this dashboard is built to catch.

Offline-first, simulated data

The frontend runs entirely in the browser with no login and no external service, so it keeps working offline. An optional backend is included in backend/ — it stores the same simulated mission in Supabase (Postgres) and exposes the same scoring through API endpoints. See the README for the Supabase setup (free project, run backend/supabase/schema.sql, copy the keys to .env, then npm run seed).

Decision support only — not a medical device. All data is simulated.
